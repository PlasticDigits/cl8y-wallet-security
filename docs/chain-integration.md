# ABI v1 and chain integration

`api/src/chain.rs` is an adapter to the contract lead's actual token `wallet_security`, `security_config`, `recovery`, CW20 `balance`/`token_info`, and controller `config`/`guard` queries. `CHAIN_REGISTRY_JSON` is an operator-only reviewed registry: HTTPS RPC/LCD origins, chain-bound token/controller addresses and exact expected code IDs, ABI Git SHA, starting height, and optional actual gas price. No registry or URL is accepted from public requests. No deployment identity is supplied in source; a missing registry is an explicit unavailable feature, not a coverage claim.

Every live read checks node network/sync, selects a height two blocks behind head, verifies code identities/controller binding and requires the LCD's `x-cosmos-block-height` response to match the requested height. Public RPC/LCD operators are trusted data providers; this service is not a cryptographic light client. Native coins and unlisted/unmigrated contracts are uncovered. An unavailable query never becomes a default policy. Chain height and time come from the actual block header.

Ingestion verifies checkpoint hash/parent before advancing. At most five finalized blocks advance in one bounded transaction and one tick is bounded to 40 seconds. Successful transaction receipt identity is chain+tx hash+event index; semantic identity includes chain+emitter+action+affected source/wallet+globally unique contract nonce. Only six exact ABI timer-start actions enqueue notices. Transfer events do not notify. Unknown emitting contracts are skipped before strict timer parsing, preventing an unrelated permissionless event from poisoning the checkpoint. Allowed-contract ambiguity, wrong identity, failed/missing receipts, or finalized divergence halts advancement and reports unavailable; do not automatically rewind a finalized warning ledger.

Checkpoint, receipt, timer and notification outbox commit together. Controller-wide timers create durable fanout jobs; each worker tick processes at most five jobs and 100 verified contacts per job. Backlog/failed counts are visible in worker status. The same event/contact/template unique key prevents replay duplication. A hash mismatch requires independently checking the trusted endpoint and actual canonical chain, then an agent-owned recovery decision; never erase already-sent notices to fabricate clean state.

Source references: [wasmd smart-query route](https://github.com/CosmWasm/wasmd/blob/main/proto/cosmwasm/wasm/v1/query.proto), [host-first contract event identity](https://github.com/CosmWasm/wasmd/blob/v0.61.15/x/wasm/keeper/events.go). Local fixture checks use an owned loopback server, synthetic receipts, and a disposable PostgreSQL database; they are not live-chain or deployment evidence.
